# Sale Page

เปลี่ยนสิ่งที่ขายให้เป็นหน้าเว็บขายหน้าเดียว พร้อมส่งลิงก์ปิดการขายในแชทได้ทันที — ถามสั้น ๆ เฉพาะสิ่งที่หน้าขายต้องมี แล้วสร้างเป็นไฟล์ HTML ไฟล์เดียว ใช้ได้ทุกที่ ไม่ต้อง build

## Ground rules

- Converse in the user's language. If the user writes Thai, use easy-to-read Thai and keep technical terms in English where that aids shared understanding.
- Separate **facts** (answerable from the conversation, files, or an existing brief — find it, never ask it), **decisions** (always the user's), and **assumptions** (must be labeled).
- Ask exactly one question at a time; every decision question carries a recommendation and a short reason.
- Never fabricate claims. รีวิว ยอดขาย ตัวเลข วันหมดเขต ส่วนลด หรือคุณสมบัติที่ผู้ใช้ไม่ได้บอก — ใช้ placeholder `[รอข้อมูลจริง: ...]` เสมอ แล้วสรุปให้ผู้ใช้เติมเองตอนส่งมอบ
- Nothing is built until the user confirms the Sale Page Spec.

## Step 0 — Recon (ก่อนถามอะไร)

Check only the context the user has given access to: the conversation, attached files, `WORKING-BRIEF.md` from Ask Me, the `briefs/` folder, brand documents, and earlier sale pages for the same outcome.

- ถ้าเจอ Working Brief ของ outcome เดียวกัน → ใช้เป็น source of truth แล้วถามเฉพาะช่องที่ brief ไม่ตอบ
- เข้าแบบ execute: `/sale-page execute <path/to/WORKING-BRIEF.md>` → อ่าน brief ก่อน แล้วข้ามไป Step 2 ทันที ไม่ถามซ้ำสิ่งที่ brief ตอบแล้ว
- สรุปสั้น ๆ ว่า recon เจออะไร ก่อนคำถามแรก เพื่อให้ผู้ใช้เห็นว่าอะไรจะไม่ถูกถามซ้ำ

## Step 1 — Interview สั้น

ถามเท่าที่หน้าขายต้องมีเท่านั้น เดินตามลำดับนี้ ข้อไหนตอบแล้วหรือเจอใน context ให้ข้าม:

1. **ประเภทหน้า** — สินค้าเดียว · คอร์ส/ความรู้ออนไลน์ · บริการ/จอง/นัดหมาย (กำหนดโครงหน้าทั้งหมด ถ้าไม่ชัดต้องถามก่อนเสมอ)
2. **สิ่งที่ขาย** — ชื่อ จุดขายหลัก 2–3 ข้อ และ "ทำไมต้องของเรา"
3. **ราคาและแพ็คเกจ** — แพ็คเกจให้เลือกกี่แบบ ส่วนลดเมื่อซื้อมาก ค่าส่ง/เงื่อนไข *(mandatory)*
4. **ออฟเฟอร์ปิดการขาย** — ของแถม การรับประกัน เงื่อนไขจริงที่ช่วยตัดสินใจ (ไม่มีก็ไม่ต้องมี — ออฟเฟอร์ปลอมไม่มีใน skill นี้)
5. **ช่องทางรับออเดอร์** — ฟอร์มในหน้า → Google Sheet · ปุ่มแชท (LINE/WhatsApp) · โอนเงิน+แจ้งสลิป *(mandatory)*
6. **ภาษาและโทนดีไซน์** — ภาษาของหน้า โทนสี ความรู้สึกที่ต้องการ
7. **ข้อมูลที่ยังไม่มี** — ภาพสินค้า เลขบัญชี/QR รีวิว — ตกลงใช้ placeholder ไปก่อน แก้ทีหลังได้

**Mandatory minimums — ถามเสมอแม้ผู้ใช้เร่ง:** (1) ราคาและแพ็คเกจ (2) ช่องทางรับออเดอร์

รูปแบบคำถาม:

```text
Question: <หนึ่งการตัดสินใจ>
Recommendation: <คำตอบที่แนะนำ>
Because: <เหตุผลสั้น ผูกกับการปิดการขายหรือข้อจำกัด>
```

## Step 2 — Sale Page Spec

ก่อนสร้าง แสดงตาราง spec ที่ทุกแถวมีที่มาแน่นอน:

- ✅ **ถามแล้ว** — ผู้ใช้ตอบ (อ้างคำตอบสั้น ๆ)
- 📄 **จาก context** — อ้างชื่อไฟล์/ข้อความที่เจอ
- ⚠️ **สมมติฐาน** — ระบุสมมติฐานและผลกระทบถ้าเปลี่ยน

แถว: ประเภทหน้า · สิ่งที่ขาย+จุดขาย · แพ็คเกจ/ราคา · ออฟเฟอร์ · ช่องทางรับออเดอร์ · ภาษา/โทนดีไซน์ · รายการ placeholder

แล้วถามคำถามเดียว: ยืนยัน spec นี้ หรือแก้ตรงไหน? ถ้าแก้ กลับไปถามทีละข้อจนยืนยัน

## Step 3 — Build

### ค่าเริ่มต้นทางเทคนิค (เว้นแต่ผู้ใช้บอกอื่น)

- ไฟล์ HTML ไฟล์เดียว — HTML+CSS+JS รวมในไฟล์ ไม่มี build step ไม่มี dependency หนัก
- Mobile-first — ผู้ซื้อเปิดลิงก์จากแชทบนมือถือเป็นหลัก
- ภาษาไทยทั้งหน้า (ตาม spec) ฟอนต์ระบบ ไม่โหลดเว็บฟอนต์หนัก
- Open Graph ครบ — แชร์ใน LINE/IG แล้วมี preview ชวนคลิก
- ปุ่ม CTA ลอยติดล่างจอบนมือถือ กดแล้วเลื่อนไปฟอร์ม/จุดสั่งซื้อเสมอ
- บันทึกไฟล์: ถ้ามีโฟลเดอร์ brief ของ outcome นี้อยู่ วาง `index.html` ที่นั่น ไม่มีก็สร้าง `briefs/<YYYY-MM-DD>-<short-name>/index.html` เว้นแต่ผู้ใช้ระบุที่อื่น

### โครงหน้าตามประเภท

| Section | สินค้าเดียว | คอร์ส/ความรู้ | บริการ/จอง |
|---|---|---|---|
| Hero | ภาพสินค้า + ชื่อ + ประโยชน์เด็ด + CTA | ผลลัพธ์ที่ผู้เรียนจะได้ + CTA | บริการ + เมื่อไหร่/ที่ไหน + CTA |
| ปัญหา | — (แทรกในจุดขายได้) | ปัญหาที่ผู้เรียนเจอก่อน | ปัญหาที่ลูกค้าเจอก่อน |
| เนื้อหา | จุดขาย 2–3 ข้อ + รายละเอียดสินค้า | หลักสูตร ได้เรียนอะไร แบบไหน | บริการครอบคลุมอะไร รอบ/วันที่/เวลา |
| หลักฐาน | รีวิว/ภาพจริง (placeholder ถ้ายังไม่มี) | ผู้สอน เวทีที่เคยทำ ผลงานผู้เรียน | ผลงาน/ตัวอย่างงาน/รีวิว |
| ราคา | แพ็คเกจ 2–3 แบบ + ค่าส่ง | ราคาคอร์ส + สิ่งที่ได้ทั้งหมด | ราคา + เงื่อนไขการจอง/มัดจำ |
| ออฟเฟอร์ | ของแถม/ส่วนลดซื้อมาก | โบนัส/รับประกันความพึงพอใจ | ช่วงโปร/แพ็คเกจรวม |
| วิธีใช้/ขั้นตอนถัดไป | วิธีชง/ใช้/เก็บ | วิธีเรียน เริ่มได้เมื่อไหร่ | ขั้นตอนการจอง สิ่งที่ต้องเตรียม |
| FAQ | 4–6 ข้อที่ขัดข้องใจจริง | 4–6 ข้อ (เก่งไหม/ไหวไหม/เรียนยังไง) | 4–6 ข้อ (ยกเลิก/เลื่อน/จ่าย) |
| ปิดการขาย | ฟอร์ม/ปุ่มสั่งซื้อ | ฟอร์มสมัคร | ฟอร์มจอง/เลือกรอบ |

ตัด section ที่ไม่มีข้อมูลจริงออก — หน้าสั้นที่จริง ดีกว่าหน้ายาวที่แต่ง

### กติกาคำ copy

- Headline พูดถึงผลลัพธ์ของผู้ซื้อ ไม่ใช่คุณสมบัติของสินค้า
- ใช้ภาษาเดียวกับที่ลูกค้าใช้เล่าปัญหาตัวเอง
- ราคาที่ดูคุ้ม แสดงเป็นหน่วยที่เทียบได้ เมื่อช่วยตัดสินใจ (ต่อแก้ว ต่อวัน ต่อคน)
- Urgency และของแถมต้องมีจริงเท่านั้น
- ปุ่มทุกจุดนำไปสู่การสั่งซื้อ ไม่มีทางตัน

### รับออเดอร์

- **ฟอร์มในหน้า → Google Sheet (Apps Script):** ฟอร์มถามเฉพาะ field ที่จำเป็น (ชื่อ เบอร์โทร ที่อยู่ แพ็คเกจที่เลือก วิธีชำระเงิน) ส่งแบบ `no-cors` fetch ไป Apps Script URL ที่ config ไว้จุดเดียวบนหัวไฟล์ และแนบคู่มือตั้งค่า 1 หน้า (สร้าง Sheet → วาง script → Deploy → วาง URL) ไว้ข้างไฟล์หน้าขาย
- **ปุ่มแชท:** ปุ่ม LINE/WhatsApp พร้อมข้อความสั่งซื้อสำเร็จรูปในลิงก์
- **โอนเงิน+สลิป:** แสดงเลขบัญชี/QR (placeholder ถ้ายังไม่มี) + ขั้นตอนยืนยันสลิปชัดเจน

### ภาพ

- โครงภาพเป็น placeholder ที่แทนที่ด้วยรูปถ่ายจริงได้ง่าย — ใช้ id/class ที่ชี้บอกจุดวางรูป และคอมเมนต์ในโค้ด
- ถ้าผู้ใช้ขอภาพ AI — สร้างตามโทนดีไซน์ที่ตกลง และย้ำว่าเปลี่ยนเป็นรูปจริงได้ภายหลัง

## Step 4 — ตรวจก่อนส่งมอบ

ตรวจทุกข้อก่อนบอกว่าเสร็จ และรายงานผลต่อข้อ:

1. เปิดบนมือถือได้ ดูดี อ่านง่ายบนจอเล็ก
2. ข้อมูลครบตาม spec — จุดขาย ราคา ทุกแพ็คเกจ ออฟเฟอร์
3. ปุ่ม/ลิงก์ทุกจุดทำงาน นำไปสู่การสั่งซื้อ ไม่มีทางตัน
4. ฟอร์มกรอกแล้วข้อมูลตกใน Google Sheet จริง (หรือช่องทางที่เลือกทำงานจริง)
5. แชร์ลิงก์ใน LINE มี preview และชื่อหน้าชวนคลิก
6. โหลดหน้าเสร็จเร็ว — ไฟล์เดียว ไม่มีสคริปต์หนัก
7. ไม่มีคำอ้างที่แต่งขึ้น — ทุก placeholder มีคำว่า `[รอข้อมูลจริง`

## Step 5 — ส่งมอบ

- วิธีขึ้นโลก: Netlify ฟรีแบบลากไฟล์วาง (หรือโฮสต์ที่ผู้ใช้เลือก) ได้ลิงก์ส่งแชททันที
- ขั้นตอนทดสอบ: ส่งออเดอร์ทดสอบ 1 ชิ้นจริง ตรวจว่าตกใน Sheet ครบทุก field
- สรุป "สิ่งที่ต้องเติมเอง" เป็นลิสต์เดียวจบ — เลขบัญชี/QR รูปจริง รีวิว พร้อมตำแหน่งในไฟล์ที่จะแก้

## การใช้ร่วมกับ Ask Me

- คุยกับ Ask Me แล้วมี WORKING-BRIEF.md อยู่ → เรียก `/sale-page execute <ไฟล์ brief>` สร้างต่อได้เลย ไม่ถามซ้ำ
- ยังไม่ชัดว่าจะขายอะไร อย่างไร ขายให้ใคร → เริ่มที่ Ask Me ก่อน แล้วค่อยมาทำหน้าขาย
- หน้าขายคือ **หนึ่ง outcome ต่อหนึ่งหน้า** — สินค้าใหม่หรือออฟเฟอร์ใหม่ ให้ทำหน้าใหม่ ไม่รวมกัน

## Red flags — หยุดแล้วอ่าน skill นี้ใหม่

- ถามมากกว่าหนึ่งคำถามในข้อความเดียว หรือถามสิ่งที่ recon หาเจอแล้ว
- คำถามตัดสินใจไม่มีคำแนะนำ
- เริ่มสร้างหน้าก่อนผู้ใช้ยืนยัน spec
- แต่งรีวิว ตัวเลข วันหมดเขต หรือคำอ้างใด ๆ ที่ผู้ใช้ไม่ได้ให้
- ส่งมอบหน้าที่ยังตรวจ Step 4 ไม่ครบ หรือมีปุ่มนำไปทางตัน
